# The practices' rules (v1.3.1)

Generated by the practices kit; don't edit it here. Each line is a rule of
this project. Before working in an area, read its file in
.practices/docs/: what the rule is, why (the incident), how to apply it,
how to check it. The project's CLAUDE.md wins where it says otherwise.
The skills in .claude/skills (practices-*) walk through the main jobs.

## Working rules for coding agents (.practices/docs/common/agent-working-rules.md)

- Builds run at the lowest priority
- The disk keeps a floor
- Never a new target directory
- Never `nix … path:` on a repo with a target folder
- Builds go to the build disk
- Development builds aren't installed
- Rebuild before saying "restart"
- Release only on a green main
- Quote measured CI timings
- Keep going on an agreed plan
- Screenshots don't flash the screen
- Write down what is deferred

## Commits (.practices/docs/common/commits.md)

- The subject is the outcome
- The body says why, with numbers, and how it was proven
- Co-Authored-By yes, session IDs never
- Stable IDs survive a rewritten history
- Trailers come last
- One commit identity per repository
- Pushing is stated, not assumed
- Release commits are just the version

## Changelog (.practices/docs/common/changelog.md)

- Written for users, in the product's voice
- Fixed kinds
- Same commit, dependency updates too
- The changelog is the release notes and What's new

## Not now: deferrals are written down (.practices/docs/common/not-now.md)

- Write it down in the same commit
- Fail loudly instead of a silent stub
- Decided "left as it is" is also written down

## Testing (.practices/docs/common/testing.md)

- Nothing touches the developer's machine
- A journey suite is the regression suite
- One scenario per test, run everywhere
- Failures explain themselves
- A step for every IPC call
- Red before green
- No retries for flaky tests
- Real-machine bugs become tests
- Fakes refuse what they weren't told
- A guard test per incident, proven able to fail
- Golden fixtures written by the old code
- Two implementations, one known answer
- Coverage floors only rise

## CLAUDE.md and the engineering docs (.practices/docs/common/claude-md.md)

- Rules and pointers in CLAUDE.md; detail in docs/engineering
- A handoff file is not a CLAUDE.md
- Every rule records its origin
- The owner's words, quoted and dated
- Known gaps beside the rule, not a reworded rule
- "Until <date>" notes keep the old behaviour visible
- Milestones say what was built and how it was proven
- Tried by real people: a checklist per platform

## Privacy in public repositories (.practices/docs/common/privacy-public-repos.md)

- Made-up names and documentation addresses
- Real findings live in a git-ignored local file
- A denylist the hooks refuse, failing closed
- People appear as roles

## Releases (.practices/docs/common/releases.md)

- Only a green main is released
- One command from Unreleased to the tag
- The workflow re-checks, then publishes in safe order
- A rehearsal that publishes nothing
- Slow external steps get honest timeouts
- Dependencies: the platform's packages, or bundle and own the updates

## CI and caching on GitHub Actions (.practices/docs/common/ci-caching.md)

- The workflow header
- Private repos: CI minutes are a budget
- Caches are saved by main only
- Spend the 10 GB on purpose
- The toolchain version is in the cache key
- Prune the caches a newer one replaced
- Sweep target directories you cache by hand
- One build per job
- Split the slowest suite, not the whole run
- Time limits come from measurements
- Artifacts are named per attempt
- Secrets reach only the steps that need them
- Pin third-party actions by commit

## Gates that can fail (.practices/docs/common/gates.md)

- Prove the gate can fail
- Every finding says how to fix it
- A rule is an error, or it's off with a reason
- The gate visits every file
- A ratchet for a rule you can't meet yet
- Audit only what ships; re-check every accepted advisory
- Licence notices from what ships; anything unknown fails

## Crash reports and logs (.practices/docs/common/crash-reports.md)

- Consent first: nothing starts before the user agrees
- Check every hook in the vendor's code, not its docs
- An allow-list scrubber, seeded with what the device knows
- Three tiers, three rules
- Expected refusals aren't reported

## Design before build (.practices/docs/ui/design-before-build.md)

- Proposals with options, then build "as chosen"
- The design holds only agreed designs
- Keep the design in sync with the code
- Read the design's source, never a picture
- When the agent can't edit the design: a prompt and a sync-back list
- Match one to one, verified by screenshot
- Review a proposal in its place, with fresh eyes

## An identity, in iterations, through the whole app (.practices/docs/ui/identity-pass.md)

- Identity first, before the first screen
- Get the facts right
- Iteration 1: establish the identity
- Iteration 2: a few parts, shown, iterated, agreed
- Iteration 3: the whole app, re-audited and polished
- An inventory that misses nothing
- Where the product's mark appears
- Before you show anything

## Visual craft (.practices/docs/ui/visual-craft.md)

- Tone, not outlines
- Every stroke end matches
- One object, one drawing
- A line weight per family
- Compact, not breathy
- Nothing anyone reads under 11 px
- One anatomy per job
- Show it in real context
- Words in the product's voice
- Motion with a reason

## Keyboard shortcuts the way each system writes them (.practices/docs/ui/keyboard-shortcuts.md)

- Bind the system's main modifier, not Ctrl
- Show them the way the system writes them

## Window buttons where each system puts them (.practices/docs/ui/window-buttons.md)

- macOS draws its own buttons; the header makes room

## TypeScript: code conventions (.practices/docs/typescript/conventions.md)

- Braces around every body
- Strict types, and every escape counted
- Errors are typed codes; the UI picks the words
- No direct console calls in the app
- Heavy modules load lazily, with `require`
- Every disabled lint rule has a counted reason
- Platform code behind an interface, with a test double
- Patched dependencies: why, when to remove, pinned exactly

## TypeScript: lints are errors (.practices/docs/typescript/lints.md)

- The gate: tsc and ESLint, errors only
- How `.practices/bin/lint` runs it
- The gate visits every file
- No two names that differ only by case
- Size limits

## TypeScript: testing with Jest (.practices/docs/typescript/testing.md)

- Native modules faked as in-memory stores
- Fakes refuse what they weren't told
- No real network in tests
- Jest sees only the project's tests
- Dev scripts are tested too
- A timeout is not a fix for slowness
- Coverage: measure, then set floors

## Mobile: releases and the stores (.practices/docs/mobile/releases.md)

- The version comes from the tag; native files are never edited
- Build numbers come from the CI run
- Another build of the same version: `+N`
- Release uploads are never cancelled
- A store whose secrets are missing is skipped, by name
- Signing in a throwaway keychain
- Check the artefact before the store sees it
- Store notes come from the changelog, limits checked after folding
- Every release goes to TestFlight testers; promotion is by hand
- Google Play: the first release is manual

## Mobile: devices, test accounts and walks (.practices/docs/mobile/devices.md)

- Never test on a device that holds real data
- The service's test environment, never production
- A feature is done once it is walked on a device
- A crash report from the field becomes a test
- Expected refusals from the OS aren't reported
- Config that native tools rewrite is held by tests

## Mobile: CI for iOS and Android (.practices/docs/mobile/ci.md)

- Public: every platform on every push. Private: before every release
- A compile check: device SDK, Debug, unsigned
- Pin the runner image and Xcode, with the reason
- Toolchains come from the project's own files
- The local gate builds every platform before a tag
- A build made as a check publishes nothing

## Mobile: lifecycle and screens (.practices/docs/mobile/lifecycle.md)

- Modals close when the app goes to the background
- The privacy cover lives where the OS calls it
- An action with no idempotency key runs once
- Explain before the permission prompt, and ask once
- A cold-start tap is queued, not lost
- No layout jumps
- The largest text size and Reduce Motion
