# Security

Obálka is a client for Czech data boxes (datové schránky). It handles people's mail from the state, so
a vulnerability here can expose government correspondence, sign-in credentials or a backup key. Reports
are welcome, and they are read.

## Reporting a vulnerability

**Do not open a public issue.** Use either:

- **GitHub:** the repository's **Security → Report a vulnerability** tab (private advisory), or
- **e-mail:** ondrej@dorhawk.software

Please include what you found, how to reproduce it, and what an attacker gets out of it. A patch or a
suggested fix is welcome, never required.

**Never send real credentials or real message content.** Not a data-box login, not a one-time code, not
a recovery key, not a `.zfo` or an attachment from an actual box. Use the ISDS test environment
(czebox) or redact. A report that arrives with someone's mail in it has made the problem bigger.

This is a small project with no security team behind it. Expect an acknowledgement within a few days
and an honest answer about when a fix can land. You will be credited in the release notes unless you
ask not to be.

## What is in scope

Anything in this repository: the app, its native modules, the build and release workflows, and the
documents that describe how the security-relevant parts work. Of particular interest:

- Anything that lets one data box read another box's mail or session.
- Anything that reads a saved password, a session, or a backup key outside the app's own unlock rules.
- Anything that sends government mail, credentials or diagnostics anywhere the user did not choose.
- Weaknesses in the backup encryption or the phone-to-phone transfer.

## What is not in scope

- **ISDS itself.** Bugs in the government's own system or its web services belong to its operator, not
  here.
- **A lost or shared device passcode.** The app's lock rests on the platform's own gate; a phone whose
  passcode is known to the attacker is outside what this app can defend.
- **A modified or rooted device**, or a build the user did not install themselves.
- **Reports generated by a scanner** with no working exploit and no explanation of the impact.

## What the app promises

These are the properties worth attacking, described in full in
[`.specify/memory/constitution.md`](.specify/memory/constitution.md) and
[`docs/accounts.md`](docs/accounts.md):

- **There is no backend of ours.** The app talks to ISDS directly. Mail and credentials never reach a
  server run by this project.
- **Credentials live in the platform's secure storage**, sealed under a vault key; with the app lock on,
  nothing that can sign in is readable while the app is locked.
- **The archive is encrypted at rest** (SQLCipher) and backups are encrypted with a key only the user
  holds (Argon2id with XChaCha20-Poly1305; attachments with AES-256-GCM).
- **Crash reporting is off until the user turns it on**, and never carries message content.

If you find any of those claims to be false, that is a vulnerability, and this is the right place to
say so.
